Περιγραφή
----------
Το `Process-Messenger` είναι ένα μικρό εκπαιδευτικό σύστημα ανταλλαγής μηνυμάτων μεταξύ διεργασιών χρησιμοποιώντας διαμοιραζόμενη μνήμη (shared memory) και μηχανισμούς συγχρονισμού (semaphores). Η εφαρμογή επιτρέπει σε πολλαπλές διεργασίες να δημιουργούν ή να συμμετέχουν σε «διαλόγους», να στέλνουν μηνύματα, να διαβάζουν μηνύματα και να τερματίζουν διαλόγους.

Δομή του έργου
----------------
- `src/`: πηγαίος κώδικας C της main
- `include/`: επικεφαλίδες (headers)
- `modules/`: πηγαίος κώδικας C
- `bin/`: παραγόμενο εκτελέσιμο (`chat_app`)
- `obj/`: αντικείμενα (.o)
- `Makefile`: κανόνες κατασκευής
- `README.md`: αυτό το αρχείο

Build & Εκτέλεση
-----------------
1. Καθαρισμός και κατασκευή:

```bash
make clean
make
```

2. Τρέξιμο:

```bash
make run
```

Σχεδίαση Διαμοιραζόμενης Μνήμης
-------------------------------
Η διαμοιραζόμενη μνήμη αποθηκεύει κεντρικά τις δομές `Dialogue` και `Message` καθώς και απαραίτητα πεδία διαχείρισης:

- SharedMemory
  - `Dialogue dialogues[MAX_DIALOGUES]`
	 - `id` : μοναδικό αναγνωριστικό διάλογου (int)
	 - `participants` : αριθμός ενεργών συμμετεχόντων (int)
	 - `active` : σημαία (1/0) εάν ο διάλογος είναι ενεργός
  - `Message messages[MAX_MESSAGES]`
	 - `dialogue_id` : σε ποιον διάλογο ανήκει
	 - `sender_pid` : PID αποστολέα
	 - `payload[MAX_MSG_LEN]` : περιεχόμενο μηνύματος
	 - `readers_count` : πόσοι το έχουν διαβάσει
	 - `is_free` : σημαία αν η θέση είναι ελεύθερη
	 - `sequence_num` : αύξων αριθμός για σειρά
  - `int active_app_count` : πόσες διεργασίες συνολικά είναι συνδεδεμένες
  - `long global_seq_counter` : γενικός μετρητής sequence

Συγχρονισμός (Synchronization)
-------------------------------
Για να αποφευχθούν ανταγωνιστικές προσπελάσεις στη διαμοιραζόμενη μνήμη χρησιμοποιείται ένας δυαδικός/μονοδιάστατος semaphore (ή `sem_t` εντός της shm σε Linux, ή όνομα semaphore σε macOS). Όλες οι συναρτήσεις που διαβάζουν ή γράφουν στη shm πρέπει να αποκτούν το semaphore πριν και να το απελευθερώνουν μετά.

Πολιτική πρόσβασης — παράδειγμα:
- `sem_wait(mutex)` πριν την αλλαγή shared memory
- ενημέρωση δομών (π.χ. προσθήκη μηνύματος, αλλαγή participants)
- `sem_post(mutex)` μετά το πέρας

Σειρές ενεργειών (Use Cases)
--------------------------------
Παρακάτω περιγράφονται βήμα-βήμα οι πιο σημαντικές ροές.

1) Εκκίνηση διεργασίας (startup)
	- Η διεργασία κάνει `connect_to_shm()` (mmap/shm_open) και `sem_open` ή χρησιμοποιεί το semaphore μέσα στη shm.
	- Παίρνει το lock και, αν είναι η πρώτη διεργασία (`active_app_count == 0`), αρχικοποιεί τις δομές (μηδενισμός `messages`, `dialogues`, `global_seq_counter`).
	- Αυξάνει `active_app_count` και απελευθερώνει το lock.

2) Δημιουργία διαλόγου
	- Ο χρήστης δίνει ένα `dialogue_id`.
	- Πάρτε το lock, βρείτε ένα ελεύθερο `Dialogue` slot (`active == 0`).
	- Γράψτε `id = dialogue_id`, `active = 1`, `participants = 1`.
	- Απελευθερώστε το lock.

3) Συμμετοχή σε διάλογο (join)
	- Πάρτε το lock, βρείτε το `Dialogue` με `id == dialogue_id`.
	- Αυξήστε `participants++` και απελευθερώστε το lock.

4) Αποστολή μηνύματος
	- Πάρτε lock.
	- Βρείτε `msg_slot` με `is_free == 1`.
	- Γράψτε `dialogue_id`, `sender_pid`, `payload`, `sequence_num = ++global_seq_counter`, `readers_count = 0`, `is_free = 0`.
	- Απελευθερώστε lock.

5) Ανάγνωση μηνύματος
	- Πάρτε lock.
	- Σκανάρετε `messages[]` για `dialogue_id == current` και `sequence_num > last_read_seq`.
	- Διαβάστε `payload`, αυξήστε `readers_count++`.
	- Αν `readers_count >= participants - 1` τότε `is_free = 1` (ελευθερώνεται η θέση).
	- Απελευθερώστε lock.

6) Τερματισμός διαλόγου (Terminate)
	- Όταν ένας χρήστης στέλνει το ειδικό μήνυμα `TERMINATE`, η εφαρμογή:
	  - στέλνει το μήνυμα ως κανονικό μήνυμα στη shm,
	  - παίρνει το lock και κάνει `dialogues[slot].active = 0`, `dialogues[slot].participants = 0`, `dialogues[slot].id = 0`, και ελευθερώνει (`is_free=1`) όλα τα `messages` που ανήκουν στον διάλογο,
	  - απελευθερώνει lock και η διεργασία τοπικά βγαίνει από την κατάσταση `in_dialogue`.
	- Οι υπόλοιπες διεργασίες που παρακολουθούν το διάλογο ανιχνεύουν το `TERMINATE` και επιστρέφουν στο μενού.

7) Τερματισμός εφαρμογής (exit)
	- Η διεργασία παίρνει το lock, μειώνει `participants` για τον ενεργό διάλογο (αν υπάρχει), μειώνει `active_app_count` και αν γίνει 0, αφαιρεί/καταστρέφει τα κοινόχρηστα αντικείμενα (`shm_unlink`, `sem_unlink` ή `shmctl(IPC_RMID)` ανά πλατφόρμα).

Συχνά προβλήματα
------------------
- "ID exists!" μετά από τερματισμό: σημαίνει ότι κάποια διεργασία κρατά ακόμη το slot. Κλείστε όλες τις διεργασίες (`pkill -f chat_app`).
- Σφάλματα σύνδεσης shared memory/semaphore: βεβαιωθείτε ότι έχετε δικαιώματα και ότι δεν υπάρχει σύγκρουση ονομάτων.
